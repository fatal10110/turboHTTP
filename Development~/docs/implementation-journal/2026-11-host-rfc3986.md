# 2026-11 Wire host checked as an RFC 3986 host (#340)

## What
`HttpAuthority.FormatHost` (Host, `:authority`, absolute-form target, CONNECT authority) now
rejects, with `HttpFieldValidationException` (transport: non-retryable `InvalidRequest`, message
without the host):

- an empty or null host. Unity Mono parses `http://-ü.de/` and `http://<70 a>ü.de/` with
  `Host == IdnHost == ""`; before this change `FormatHost("")` returned `""`.
- ASCII output that is not a DNS name. `ü` + U+00A0 + `.de` maps to `xn-- -dha.de` on .NET 8 and
  Mono (IDNA2003 maps U+00A0 to SP), which was sent unchanged.
- a bracketed value without an IPv6 address, and an IPv6 literal with characters other than hex
  digits, `:` and `.`.

The DNS-name rule is labels of 1-63 characters from letters, digits, `-` and `_`, separated by `.`,
at most 253 characters, with one optional trailing `.` (an absolute name). IPv4 addresses pass the
same rule.

`RawSocketTransport.DispatchCoreAsync` calls `HttpAuthority.HostFromUri` right after the scheme
check, so an invalid host fails before the cleartext policy, the proxy and any socket. Before this,
the HTTP/1.1 Host was only built after connect and TLS, and the CONNECT authority after the proxy
socket was open. HTTP/2 already built `:authority` before taking a stream id (`Http2Connection.cs`
`DispatchAsync`), and it now gets the new rule through the same `FormatHost`.

## Files
- `Runtime/Transport/Internal/HttpAuthority.cs`: empty check, `IsDnsName`, `IsIPv6Characters`,
  the bracket check, and `InvalidHost()`.
- `Runtime/Transport/RawSocketTransport.cs`: the pre-socket host check (12 lines, after the scheme check).
- `Tests/Runtime/Transport/HttpAuthorityRfc3986Tests.cs`: `FormatHost` valid and invalid cases,
  `FromUri` and the serializer with the #340 inputs, and transport sends through a never-accepting
  loopback proxy (absolute-form and CONNECT) asserting `InvalidRequest` and no pending connection.
- `Tests/Runtime/Transport/Http2/Http2ConnectionTests.HostRfc3986.cs`: `:authority` with
  `xn-- -dha.de` fails as `InvalidRequest`, and the next request still gets stream 1.

## Decisions
- Only DNS-name characters are accepted, not the full RFC 3986 reg-name set (pct-encoded and
  sub-delims). A Host / `:authority` names a host that a resolver must find, and `%`, `!`, `~` and
  the others never occur in DNS host names. `_` is allowed, as the issue suggests, because
  resolvers accept it. Hyphen position is not checked: RFC 3986 allows it, and the resolver reports
  such names.
- `IdnMapping.UseStd3AsciiRules` is not set. Mono and .NET differ in IDNA, and the explicit check
  after conversion is the same on both.
- IPv6 syntax is not fully re-parsed (`Uri` already did); only the character set is checked.
- A caller-set `Host` header (`Http11RequestSerializer`, header already present) still bypasses
  `HttpAuthority`. That was already the case before #340, and the acceptance criteria do not cover it.

## Deferred
- WebSocket: `TurboHTTP.WebSocket` builds its own Host header from `Uri.Host` and cannot use the
  internal `HttpAuthority`, which lives in Transport. #309 (v1.1) owns that and was amended with
  the #340 rules: empty host, DNS-name check after the A-label conversion.
