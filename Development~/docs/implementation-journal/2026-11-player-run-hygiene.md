# 2026-11 Player-run hygiene: bounded test-server Dispose, per-target skip baselines, short-lived test certificate (#349, #341, #332)

Test-side and tooling fixes for unfiltered player runs (iOS simulator, Android emulator/device, #99).
No Runtime/ change.

## What

- **#349, bounded Dispose of the loopback test servers.** `WebSocketTestServer` and
  `WebSocketTestProxyServer` waited for their accept loop (and the server for every handler) with
  `GetAwaiter().GetResult()` and no bound. On IL2CPP a pending `AcceptTcpClientAsync` or socket read is
  not always ended by `Stop`/`Dispose`, and `Dispose` usually runs on the main thread outside any
  `AssertAsync` bound, so iOS run 6 stalled. Both servers now track accepted sockets, and `Dispose`
  (idempotent) stops the listener, closes every accepted socket (which ends a handler whose read ignores
  its token), then waits for the accept loop and the handlers at most 2 s in total
  (`BoundedShutdown.DefaultBound`). A task still running is abandoned with `AbandonableTask.Observe`
  (a later fault is observed) and one warning is logged. The proxy's per-client handlers were
  fire-and-forget; they are tracked now, and it exposes `ConnectionCount`. The in-memory
  `LoopbackWebSocketTransport` of `WebSocketConnectionPhase18FixesTests` gets the same bound.
  `WebSocketCleartextPolicyTests` saves and restores `CleartextTrafficPolicy.PlatformPolicy` in
  `[SetUp]`/`[TearDown]`, and the refusing-host case builds and disposes its server and transport inside
  the `AssertAsync` bound.
  The other loopback servers named in the brief already bound their waits (`Wait(5 s)`, `WhenAny`) or
  have no wait; they are unchanged.
- **#341, per-target skip baselines.** `skip-baseline.txt` keys are run targets: `EditMode`/`PlayMode`
  (host editor, `run-tests.sh`), `Player-Android` (`run-device-tests.sh`, and `run-emulator-tests.sh`
  through it) and `Player-iOS`. Each player skip is listed with its reason. `run-device-tests.sh` passes
  `Player-Android`; `summarize_results.py` already looked the key up verbatim, its docstring now says so.
  The host `PlayMode` number stays 3. `testing.md` had a stale `PlayMode 4`.
- **#332, short-lived self-signed certificate.** Apple rejects the 100-year `TestLocalhostCertificate`
  with -67901 (`errSecCertificateValidityPeriodTooLong`) before its anchor check, so the "no trust
  anchor" cases saw `Invalid`/`bad_certificate` instead of `UntrustedRoot`/`unknown_ca`. A second
  fixture, `TestShortLivedLocalhostCertificate` (397 days, same identity, PKCS#12 SHA1/3DES, registers
  no test anchor), generated by the new `Tools~/test-certs/gen_short_lived_localhost_cert.py`, is used by
  `ServerCertificateVerifierTests.SelfSignedLeaf_WithoutAnchor_IsUntrusted` (verified at the middle of
  the validity period) and both `BouncyCastleChainValidationTests.Loopback_SelfSignedWithoutAnchor_*`
  cases. Both still assert a rejection everywhere. `TestShortLivedLocalhostCertificateTests` fails when
  the validity period exceeds 398 days or fewer than 30 days remain before `NotAfter`, with the
  regeneration command in the message. Production mapping is unchanged (-67901 stays `Invalid`).

## Decisions

- #349: one shared 2 s bound per `Dispose` (lane note), waited through the task's wait handle like
  `AssertAsync` (no banned `Task.Wait`/awaiter). The cancellation source is disposed only when every task
  ended, because an abandoned task may still read its token.
- #341: per-target keys rather than `[UnityPlatform]`: every player skip goes through
  `TestRequirements.IgnoreEnvironment` with a runtime capability check (a verifier, a reporting
  finalizer, file locking), not a pure platform fact, so attribute scoping would hide real coverage
  changes. `Player-iOS` is recorded data: no script reads it, because `build-ios-test-player.sh` belongs
  to the iOS handoff of another session and was not edited.
- #332: option (a). Generating at test time is not workable: Mono has no `CertificateRequest`, the
  vendored BouncyCastle has no certificate generator and the test assembly does not reference it. A
  second fixture rather than shortening the shared certificate, so only these cases carry an expiry.
  398 days (Apple's limit for TLS server certificates issued since 2020-09-01; the issue's 825 days is the
  older limit), generated with 397 for margin.
