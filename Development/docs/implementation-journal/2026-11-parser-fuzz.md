# 2026-11 parser-fuzz (#112)

Wave run w1102, lane parser-fuzz. One PR.

## What

- **Fuzz harness** `Tools~/fuzz/`: a net8.0 console app (`TurboHTTP.Fuzz.csproj`) that links the
  shadow-build DLLs, like `Tools~/autobahn`. Eight targets (`Targets.cs`), each with an oracle that
  accepts only the typed failures the parser documents:
  `h1-response` (`Http11ResponseParser.ParseAsync`), `h1-chunked-body` (`Http11ResponseBodySource`
  through a caller buffer of 1-64 bytes), `hpack` (a block sequence on one `HpackDecoder`),
  `h2-frames` (`Http2FrameCodec` + `Http2Settings.ParsePayload`/`Apply`), `h2-connection` (the whole
  `Http2Connection` read loop over `H2FuzzStream` with a GET open on stream 1), `ws-frames`
  (`WebSocketFrameReader` + `MessageAssembler` + inflate of RSV1 messages), `ws-inflate`
  (`PerMessageDeflateExtension.TransformInbound`), `json` (`JsonReader`).
- **Drivers** (`Program.cs`): `replay` (corpus once), `mutate` (fixed-seed mutation loop with a hang
  and memory watchdog, no coverage guidance), `libfuzzer` (SharpFuzz + libfuzzer-dotnet, only in a
  `-p:FuzzDriver=libfuzzer` build). `run.sh` wraps all three; for libfuzzer it rebuilds into a clean
  `.build/fuzz/bin` and instruments the DLL copies there, never `.build/shadow`.
- **Corpus** `Tools~/fuzz/corpus/<target>/seed-*` (72 files), generated by `Seeds.cs` from the inputs
  the parser tests use plus RFC 7541 Appendix C and RFC 7692 Section 7.2.3 examples.
  `.gitattributes` marks it binary so line endings stay byte-exact.
- **CI** `.github/workflows/fuzz.yml`: one libFuzzer job per target. Pull requests touching
  `Runtime/Transport/Http1|Http2`, `Runtime/WebSocket`, `Runtime/JSON` or `Tools~/fuzz` run up to 1M
  executions or 10 minutes per target; weekly and manual runs take the dispatch budget. libfuzzer-dotnet
  is compiled with clang from a pinned commit whose source hash is checked.
- **Unity regression tests**: `Tests/Runtime/SeededMutator.cs` (the same mutator) and
  `Tests/Runtime/{Transport/ParserFuzzRegressionTests, WebSocket/WebSocketFuzzRegressionTests,
  JSON/JsonFuzzRegressionTests}.cs`: fixed seed 112, inline seeds, 3000-5000 inputs per target, the
  same oracles as the harness (h2-connection stays out of Unity: it needs thread-pool loops and a
  wall-clock hang bound).
- `Runtime/Transport/AssemblyInfo.cs`: `InternalsVisibleTo("TurboHTTP.Fuzz")`, next to the
  `TurboHTTP.TlsInterop` precedent. No production code changed.

## Decisions

- **Separate workflow.** `fuzz.yml` instead of a job in `ci.yml`: libFuzzer runs are time-bounded,
  not deterministic, and the ci-host-unity lane edits `ci.yml`. The fuzz job is not part of the
  required `ci` aggregate.
- **libFuzzer only in CI.** Locally, fetching and running libfuzzer-dotnet and the SharpFuzz
  instrumenter was not permitted in this environment, so the local runs used the mutation driver.
  The SharpFuzz package reference is conditional, so the default harness build restores nothing new.
- **Target via environment.** libfuzzer-dotnet passes a single `--target_arg`, so `run.sh` names the
  target in `TURBOHTTP_FUZZ_TARGET`.
- **HTTP/1.1 oracle.** `IOException`, `FormatException` and `NotSupportedException` (a transfer coding
  other than chunked, `Http11ResponseParser.cs:515`) are the parser's contract; `RawSocketTransport`
  maps all three to `UHttpException` (`RawSocketTransport.cs:652-684`). The chunked decoder rejects
  bare LF after chunk data, which RFC 9112 Section 2.2 allows (the MAY applies to the start line and
  fields).
- **HTTP/2 scope.** Both the codec alone and the whole read loop. `H2FuzzStream` returns an empty
  SETTINGS plus SETTINGS ACK, then holds the input until the client has written its HEADERS frame, so
  the padding, priority and CONTINUATION paths run against an open stream. A read-loop failure whose
  root cause (through `UHttpError.InnerException`) is not a protocol, compression or I/O error is a
  finding, because the loop's `catch (Exception)` would otherwise hide it. `OperationCanceledException`
  is allowed too: when the read loop closes the connection, a sender waiting for its send window
  gets one (`Http2Connection.Send.cs`, `ThrowIfConnectionClosedForSend`).
- **permessage-deflate.** The targets negotiate `server_no_context_takeover`: inbound context takeover
  is not implemented and `AcceptNegotiation` rejects a response without it.
- **Lane brief correction.** `ParsedResponse` is not `IDisposable`; the targets call
  `ReleaseBodyBuffers()` in `finally`.

## Deferred

- None. The coverage-guided runs (1,000,000 libFuzzer executions per target, 0 findings) are in
  Verification. `h2-connection` needs about 530 s of the 600 s PR budget for 1M runs.
