# 2026-11 — BouncyCastle certificate chain validation and RFC 6125 host matching (#33)

Part of #33 (v1.0-alpha). Follow-up for the native/device part: #239.

## What

The BouncyCastle provider accepted any chain whose leaf had a matching name and valid dates
(`ValidateCertificateChain` was a `#warning`), matched `*.com` against `example.com`, used the CN
even with a SAN, and ignored iPAddress SANs. It now validates per decision A on #141 (validation
outside BC):

1. Host identity (RFC 6125 s6) — `Runtime/Transport/Tls/TlsCertificateNameMatcher.cs`: target is
   `TlsHostName.ToTargetHost` (A-label, bare IP, no trailing dot); IP literals match only iPAddress
   SANs (same family, same octets); dNSName otherwise; CN only without any subjectAltName (and only
   a single CN); wildcard only as the full left-most label with two or more labels after it.
2. Leaf EKU must permit serverAuth when present; leaf validity period.
3. Path validation — `Runtime/Transport/Tls/ServerCertificateVerifier.cs`: `X509Chain` on the
   server's DER chain (Editor/desktop), revocation `NoCheck`, `UrlRetrievalTimeout` 5 s (the
   evaluation runs on the handshake thread and the 30 s deadline cannot interrupt it, #142). The
   status flags decide, not `Build()`'s return value. iOS/Android devices: no verifier, every chain
   rejected (fail closed) — native SecTrust/TrustManager bridges are #239.
4. `TlsUtilities.CheckPeerSigAlgs(context, path)` on the platform-built path (leaf -> anchor),
   certificates wrapped by `TlsCrypto.CreateCertificate`; `ArgumentException` from the restricted
   key factory and `unsupported_certificate` are caught and rethrown as fatal alerts.

Alerts: bad_certificate (host, EKU, malformed, invalid path), certificate_expired, unknown_ca,
certificate_unknown (no verifier), unsupported_certificate — all in
`BouncyCastleTlsProvider.IsNonTransientAlert`, so `AuthenticationException` ->
`UHttpErrorType.CertificateError`. The `#warning` and the NON-PRODUCTION remarks are gone.

## Decisions

- Verifier and matcher live in Transport (engine-free, reachable from tests via InternalsVisibleTo,
  reusable by a future SslStream hook); all BC API use stays in `TurboTlsAuthentication.cs`, a strip
  closure root. Every BC API used exists in the current Lib (compiles); the next strip must take the
  new file as a root. No re-strip needed now.
- Test trust anchor: `ServerCertificateVerifier.AddTestTrustAnchor` (internal, copy-on-write array
  under a lock, `Volatile` reads). With anchors, `AllowUnknownCertificateAuthority` is set for
  `Build()` only; the result is still rejected unless the built root equals an anchor. Production
  never registers one. `TestLocalhostCertificate.TryLoad()` registers the loopback certificate, so
  every existing BC loopback test keeps working without per-file edits; the new tests clear it and
  show the same certificate is rejected (`unknown_ca`, `CertificateError` through the transport).
- Native iOS/Android verifiers not guessed without a device: devices fail closed, #239 (v1.0-alpha).
- Optional user validation callback (original fix step 3): SslStream has none; deferred to #117.
- CN fallback kept only without a SAN extension (RFC 6125 6.4.4); no public-suffix list
  (`*.co.uk` matches `a.co.uk`); RFC 6125 does not require one.
