# 2026-10 h1-reuse: HTTP/1.1 connection-reuse safety (#37, #43, #109, #42, #45, #48)

## What
- **#37** An expect-continue request whose body was not completely sent (early final response,
  failed or partial body send) never returns its connection to the pool: `KeepAlive` is forced to
  false on the head before `Http11ResponseBodySource` is built (the empty-body path pools inside its
  constructor). The server may read and discard the declared body (RFC 9110 sec 10.1.1).
- **#109** Single rule "Send failure vs early final response" (phase 22b.1 section 6a): after a
  failed body send the head is still read; a non-2xx final response is returned to the caller
  (event `TransportExpectContinueBodySendFailed` records the failure and status), a 1xx/2xx head or
  no head surfaces the send failure. Both expect branches (after 100 and after the timeout) now use
  the same helper (`CompleteExpectContinueHead`); before, the timeout branch returned a final head
  and ignored the send failure while the 100 branch threw. 417: no automatic retry, documented
  (section 6j) and tested; opt-in retry tracked in #214. Validation matrix added with the
  BouncyCastle row (PASS, `BouncyCastleDuplexStreamTests.cs:152`; #36 closed).
- **#43** The parser forces `KeepAlive = false` for 101 at the data level (RFC 9110 sec 15.2.2,
  sec 7.8), so every path (lease, expect, buffered) closes after a 101. Chosen over rejecting
  `Upgrade` requests: nothing in Runtime sends Upgrade through RawSocketTransport, and closing does
  not break callers that send one.
- **#42** The stale reused-connection retry filter (direct and proxy copies) also matches EOF
  before the status line (`IsConnectionClosedBeforeStatusLine`), via `IsStaleReusedConnectionFailure`.
  Fresh connections still surface the error.
- **#45** Caller cancellation during the expect-continue wait left a head read pending while the
  `finally` returned the reader's ArrayPool buffer. Now the connection is closed first, the read is
  awaited (bounded, 2 s), and only then is the buffer returned; a read that outlives the bound keeps
  its buffer (abandoned to the GC, never pooled).
- **#48** `Http11RequestWriteState.HasWrittenCompleteMessage` is set once the last byte of the
  message was handed to the stream (head for bodiless requests). Non-idempotent requests are
  replayed only when no body byte was committed and the message was not completely written
  (RFC 9110 sec 9.2.2). A POST whose head was written but whose body write failed before any byte
  is still replayed (the server cannot have a complete request).

## Decisions
- Close instead of finishing a small replayable body after an early final response (the issue's
  optional variant): the server rejected the body, and a closing server turns the upload into a
  broken pipe.
- Journal decision 4 of `2026-03-phase22b.1-http2-expect-and-forward-proxy-streaming.md`
  (transport-failure precedence) is narrowed: it still holds for 1xx/2xx heads (no silent success
  for a partial upload), but a non-2xx final response wins (RFC 9112 sec 9.5).
